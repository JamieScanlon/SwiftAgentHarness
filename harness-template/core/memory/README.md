# Memory

Cross-session, durable knowledge: project-instruction files like `AGENTS.md` / `CLAUDE.md`, agent-written memory that survives session boundaries, layered scopes (user / project / team / local), and the read-time and write-time mechanics that keep memory useful instead of stale.

In-session compaction — condensing a single conversation's history — is its own top-level topic under [../context-engine/](../context-engine/). This area is about state that persists *across* sessions.

Memory sits in `core/` as the eighth inner-ring layer. It earns that placement because — unlike Tools, Skills, or MCP servers — it is the one persistent knowledge resource the [Context Engine](../context-engine/) auto-loads on every turn *without* the model invoking it. (Tools/Skills/MCP, by contrast, are model-invoked through the Tool System dispatcher; their registries are Tool System concerns.) Memory also has its own write side — consolidation, decay, scoring, recall sub-agents — that is too substantive to bury inside the Context Engine. See [../README.md](../README.md) for the full eight-layer ring.
